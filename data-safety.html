Data Safety Sheet

Last Updated: July 14, 2026

1. Google Play Data Safety Disclosures

Under Google Play Developer console guidelines, we publish the following verified details detailing what parameters leave the client device:

Data Type Shared / Transmitted Verification Detail
Location Not Shared Although manifest declarations exist, no coordinates are retrieved via GPS. Distance metrics are calculated using static database fields.
Personal Info Transmitted Name, email, and photo URL synced to Google Firebase Auth and Firestore. Optional phone number.
App Activity Transmitted Reviews (ratings, comments <= 1000 characters) and custom wishlist board items saved in Firestore.
Financial Info Transmitted Lifetime Premium (₹199 upgrade status) checked via RevenueCat APIs. No card parameters are processed.
Device IDs Shared with AdMob Google AdID for advertisement delivery (free tier only). Deactivated upon Premium activation.

2. Security Standards

Our codebase implements the following security protocols:

  • Transit Encryption: All database operations communicate using secure HTTPS channels (TLS/SSL).
  • Cloud Security Rules: Firestore collections use permission checks to limit write privileges to the account owner.
  • Local database caching: Local databases are sandboxed. Caching databases (Hive) are not encrypted.

3. Account Erasure Scope & Limits

Selecting "Delete Account" executes the `deleteAccount()` sequence. This deletes the core user profile document `/users/{uid}`, terminates the Firebase Auth account, and clears the local Hive settings cache.
Nesting Limitations: Client-side cleanup parameters do not automatically recursively delete subcollections (reviews list `/users/{uid}/reviews` and boards `/users/{uid}/boards`) or profile pictures in Storage due to structural database nesting. Submit a request using the form below to ensure support purges all nodes from servers.
